Run your own

The whole system is free software under the AGPL-3.0. Run a private instance for yourself, your family or your team, with your own limits.

On your own Cloudflare account

This works today. Cloudflare's free plan is enough for personal use: by our estimate from Cloudflare's published limits, a free account relays on the order of 100 GB a day. Cloudflare does not charge for bandwidth.

  1. Install Bun 1.4 or later, and sign in to Cloudflare with bunx wrangler login.
  2. Get the code and build it: 
    git clone https://github.com/phibkro/file-transfer
      cd file-transfer
      bun install
      cd platforms/cloudflare
      bun run build:all
  3. Deploy: bunx wrangler deploy. Wrangler prints your instance's address on workers.dev.
  4. Optionally, attach your own domain in the Cloudflare dashboard, and set a salt for address hashing: bunx wrangler secret put ADDRESS_SALT.

On your own machine

The same server code runs on workerd, Cloudflare's open-source runtime, in one container. Any machine or provider that runs Docker will do:

docker run -p 8080:8080 -v file-transfer-storage:/srv/storage ghcr.io/phibkro/file-transfer

Put a proxy that terminates TLS in front of it (Caddy, Traefik or nginx), because browsers allow the encryption and storage this app needs only on HTTPS. Set CLIENT_ADDRESS_HEADER to the header your proxy writes the client's address into, for example x-real-ip. The settings below are environment variables there; the self-hosting guide has the details.

Limits you control

Variable Default What it limits
LIMIT_ROOMS_PER_ADDRESS_PER_HOUR 100 Transfers one network address may start per hour
LIMIT_RELAYED_BYTES_PER_ROOM 10000000000 (10 GB) Bytes relayed for one transfer
CLIENT_ADDRESS_HEADER cf-connecting-ip Where the client's address comes from; change it only behind your own proxy

On Cloudflare, set them in platforms/cloudflare/wrangler.jsonc before deploying, or in the dashboard afterwards. In the container, pass them as environment variables (docker run -e COUNTERS=on ...).

Counters, if you want them

Counting is off by default. Set COUNTERS to on to keep hourly counts of rooms, recipients, completed and failed transfers, size buckets and megabytes relayed, with nothing that identifies anyone (kept for COUNTERS_RETENTION_DAYS, 90 by default). Then set an admin token, bunx wrangler secret put ADMIN_TOKEN, and read them:

  • /admin: a page with your settings, a 48-hour chart and the totals.
  • /api/admin/counters: totals and hourly counts as JSON.
  • /api/admin/metrics: totals in OpenMetrics, which Prometheus and Grafana read. Scrape it with authorization: Bearer <your token>.

Without an admin token those addresses do not exist. Visitors can see whether your instance counts at /api/instance.
