Run your own

The whole system is free software under the AGPL-3.0. Run a private instance for yourself, your family or your team, with your own limits.

On your own Cloudflare account

This works today. Cloudflare's free plan is enough for personal use: by our estimate from Cloudflare's published limits, a free account relays on the order of 100 GB a day. Cloudflare does not charge for bandwidth.

  1. Install Bun 1.4 or later, and sign in to Cloudflare with bunx wrangler login.
  2. Get the code and build it: 
    git clone https://github.com/phibkro/file-transfer
      cd file-transfer
      bun install
      cd platforms/cloudflare
      bun run build:all
  3. Deploy: bunx wrangler deploy. Wrangler prints your instance's address on workers.dev.
  4. Optionally, attach your own domain in the Cloudflare dashboard. The salt that keeps address hashes from being reversed is generated on first use; there is nothing to set.

One-click deploy

Deploy to Cloudflare

Cloudflare copies a prebuilt version of this software into a new repository in your GitHub account and deploys it to your account, without installing anything. It asks for one optional secret, an admin token for the operator page; everything else has a default. The deploy branch it copies is built by CI from the main branch.

On your own machine

The same server code runs on workerd, Cloudflare's open-source runtime, in one container. Any machine or provider that runs Docker will do:

docker run -p 8080:8080 -v file-transfer-storage:/srv/storage ghcr.io/phibkro/file-transfer

Put a proxy that terminates TLS in front of it (Caddy, Traefik or nginx), because browsers allow the encryption and storage this app needs only on HTTPS. Set CLIENT_ADDRESS_HEADER to the header your proxy writes the client's address into, for example x-real-ip. The settings below are environment variables there; the self-hosting guide has the details.

As one program

Without Docker, download file-transfer-node for Linux (x64 or arm64), macOS (Apple silicon) or Windows from the releases page. It is the same server with the web app built in, in one file: 

mkdir storage
./file-transfer-node

It listens on port 8080 and keeps room state in ./storage; --socket-addr http=127.0.0.1:9000 and --directory-path storage=/var/lib/file-transfer change them. Put the same TLS proxy in front, and set the same environment variables.

Limits you control

Variable Default What it limits
LIMIT_ROOMS_PER_ADDRESS_PER_HOUR 50 Transfers one network address may start per hour
LIMIT_RELAYED_BYTES_PER_ROOM 25000000000 (25 GB) Bytes relayed for one transfer
LIMIT_RELAYED_BYTES_PER_DAY 100000000000 (100 GB) on Cloudflare; off in the container Bytes the whole instance relays per day (UTC); off for no daily budget
CLIENT_ADDRESS_HEADER cf-connecting-ip Where the client's address comes from; change it only behind your own proxy

On Cloudflare, set them in platforms/cloudflare/wrangler.jsonc before deploying, or in the dashboard afterwards. In the container, pass them as environment variables (docker run -e COUNTERS=on ...).

What Cloudflare's free plan carries

Cloudflare charges nothing for bandwidth. It bills the relay by Durable Object requests, counting 20 incoming WebSocket messages as one, and by the time a room is busy. Every transfer goes through the relay today, so the free plan's daily allowance is shared by everyone using your instance, and by any other Workers in the same Cloudflare account. These are estimates from Cloudflare's list prices and our load test, not from an invoice:

Per day on Workers Free About
Durable Object requests included 100,000
Requests per GB relayed 775
Relayed in total 125 GB
Full-size transfers at the defaults 5 of 25 GB, or 12 of 10 GB, or 1,200 of 100 MB
Time rooms are busy (13,000 GB-s) Runs out first only if transfers average below about 1 MB/s

When the day's requests are used up, transfers on your instance stop until the allowance resets, for everyone: new ones cannot start, and ones in progress stop. The per-address limits cannot prevent this, because five full-size transfers from one person are enough. So Cloudflare deploys come with a daily relay budget of 100 GB for the whole instance: past it, transfers stop with a message and new ones are refused until midnight UTC, and your account keeps requests for everything else. On Workers Paid, raise LIMIT_RELAYED_BYTES_PER_DAY or set it to off. On Workers Paid ($5 a month), the included million requests relay about 1,300 GB a month, and more costs roughly $0.17 to $0.64 per TB. Running it on your own machine has no such allowance: the limit is your connection.

Counters, if you want them

Counting is off by default. Set COUNTERS to on to keep hourly counts of rooms, recipients, completed and failed transfers, size buckets and megabytes relayed, with nothing that identifies anyone (kept for COUNTERS_RETENTION_DAYS, 90 by default). Then set an admin token, bunx wrangler secret put ADMIN_TOKEN, and read them:

  • /admin: a page with your settings, a 48-hour chart and the totals.
  • /api/admin/counters: totals and hourly counts as JSON.
  • /api/admin/metrics: totals in OpenMetrics, which Prometheus and Grafana read. Scrape it with authorization: Bearer <your token>.

Without an admin token those addresses do not exist. Visitors can see whether your instance counts at /api/instance.
