# Foldkit UI, Quick Share and Local Library

## Goal

Use Foldkit and Foldkit UI for every web UI surface while preserving current main's transfer, operator and site capabilities. Rebrand live sharing as Quick Share. Add an opt-in on-device metadata catalog with a default collection and reusable named collections. File adding and empty collection creation must work through the ordinary browser file input, without requiring File System Access picker support.

Integration baseline: main `5609521` (product 0.6.0). Newer direct paths, lifecycle guards, storage ownership, previews, public pages, dependency checks, deployment patches and release gates are requirements, not obsolete code to replace with an earlier implementation.

## Required journeys

1. Quick Share chooses or drops files in batches, appends more files, validates/removes/renames entries and previews them before sealing. Server limits remain visible. Explicit sealing freezes content and names, creates the link and shows progress. Send other files opens a separate transfer without terminating the existing one.
2. Share controls keep the fragment masked until reveal, copy or native Share are explicit, and QR generation/display is lazy and opt-in.
3. Recipients review the offer before data, may rename local save names, see mobile-data and insufficient-space warnings, and accept/decline only in the current lifecycle's Reviewing phase. Preserve direct/relay fallback, credits, seeded fault handling, resume, storage-open/commit guards, completion linger and late returning senders.
4. Verified files support individual Save/Preview, Save all, later save-name edits, unsaved-file leave protection, and explicit removal from the browser. Releasing a session closes network/direct resources and timers, waits for pending work and cleanup, revokes URLs and releases storage locks. No late continuation may recreate resources or publish after closure.
5. Completion summaries and copyable reports retain size, duration, speed, reconnects, network/path and edge information without filenames, links or keys. Browser storage and direct-connection settings retain their disclosure, confirmation, cross-tab lock protection and preference semantics.
6. Every local user sees a nondeletable My files collection even before opt-in. It derives all indexed membership instead of persisting another roster. Remembering is explicit and default off. Standard File Drop/file input indexes metadata/fingerprints and retains a transient native File only in browser memory, never copied contents in IndexedDB/OPFS/cloud. Optional native handles allow durable access where supported. After reload or editing a captured File, reselect/reconnect explicitly. Create an EMPTY named collection without selecting files, then edit membership and resend it.
7. Reconnection confirms the intended original but preserves the indexed/last-approved version baseline. Share reviews current bytes/fingerprints locally, including same-size/time edits, then requires explicit current-version approval before content is sent. Missing/denied originals block the entire selection. Consent epochs and revision checks reject stale cross-tab work. Opt-out forgets only catalog metadata/references and named collections, never originals; My files remains.
8. Cloud is unavailable in this delivery. Service-provided cloud storage requires an account and Premium, with no free hosted storage. Configurable self-hosted storage requires no subscription. Adding/indexing local files is not uploading or cloud synchronization.
9. Operator UI preserves public settings/limits, session-only token handling and explicit forgetting, authenticated own-API requests, authorization/counters-disabled/error states, aggregate totals, completion ratios, table and accessible 48-hour uPlot chart. Chart implementation stays isolated from transfer pages.
10. Shared site navigation/layout and all four information pages retain routes, anchors, diagrams, privacy/security disclosures, source offer and self-hosting/cost instructions. Generate their static markup through Foldkit while preserving useful no-JavaScript information pages.
11. Sandboxed previews remain an isolated opaque-origin page with strict CSP and sniff-based allowlist. Preview local Blobs via the existing message protocol, never upload or fetch their contents. Render text as text, never HTML/SVG, stop media and revoke URLs when closed. Both parent and preview-frame UI use Foldkit.

## Architecture and shared contracts

- Foldkit/UI 0.170.0 with Effect 4.1, Foldkit Vite plugin, development DevTools/MCP and official Oxlint rules. Preserve Vite+, Ultracite, ox-dep-lint, knip, Effect enforcement, Bun patches and changeset/release flow. The user's explicit Foldkit decision supersedes ADR 0020's browser-UI Effect prohibition, not its Valibot wire-contract design.
- Pure Schema-backed Model/Message/update/view; Commands for one-shot work, Subscriptions for gated event streams, ManagedResources for sessions and Mounts for element-bound foreign widgets. No legacy DOM renderer hidden behind a Mount. uPlot is a genuine existing foreign chart boundary and gets an element-owned Mount with destroy.
- Reuse current sender/recipient protocol logic, connection/direct/storage/address modules and recipientPhase transitions. Do not copy obsolete protocol adapters over current main. Existing native wire decoders and parcel bytes stay unchanged.
- UI features live under `src/features/quick-share`, `receive`, `library`, `settings` and `administration`. Each cohesive Foldkit module exports its Model, Message, initialization, pure update/view and owned lifetimes. `src/app` owns composition and Runtime entry. Library OutMessage.RequestedQuickShare carries private Files; sender boot accepts Files and an explicit auto-seal choice. Ordinary Quick Share remains batch-first and explicitly sealed.
- `src/features/quick-share/session.ts` and `src/features/receive/session.ts` are UI-free session adapters. They emit private snapshots/events and expose control operations plus awaited close receipts. Session internals and keys never enter public Model fields or Command arguments. Preserve stable test handles: #files, seal button, #link, review/Accept/Decline, named rename/preview/save controls and the report hook.
- Shared presentation modules live under `src/ui/`. Preview lives under `src/capabilities/preview`; Settings lives under `src/features/settings`. FileName owns inline name editing. Stateful modules use the usual Model/Message/init/boot/update/view contract and owned lifetimes. Parents use h.submodel and Update.foldChild, never mutate child internals.
- `src/ui/privateValue.ts` uses Effect Redacted with a safe non-restorable JSON marker. Files, handles, names, links/fragments, preview payloads, operator tokens and sensitive snapshots must not enter diagnostics in plaintext. `src/app/address.ts` is the sole page-address and fragment boundary. The sandbox preview Runtime disables diagnostic recording and the bridge.
- Reuse the tested metadata catalog and private codec from the earlier branch, not its obsolete sender/recipient engines. Preserve IndexedDB v1 migration and consent fences, and distinguish received OPFS cleanup from the Local Library catalog.
- Re-jevify all 29 toolkit exports against this complete application scope, then inspect escalated source evidence. Reuse components for required interactions; do not invent features to consume a widget.
