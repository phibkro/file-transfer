# Invariants

What must always hold, whatever the network, the browsers or the servers do. Each invariant names where it is enforced and which tests show it holds; a reviewer can start here and follow the links into the code. Requirement keywords (MUST, MUST NOT) are used as in RFC 2119 and RFC 8174, and only in capitals.

The threat model (`threat-model.md`) says which attackers each invariant is meant to stop; the specs (`parcel.md`, `protocol.md`) say how.

**Status** says how strongly an invariant is backed:

| Status     | Meaning                                                                                               |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| tested     | Enforced in code, and a test fails when it is broken (a negative control or a fault that provokes it) |
| enforced   | Enforced in code, with tests of the normal path only                                                  |
| documented | Stated in a spec or a decision, not yet enforced or checked by code                                   |
| open       | Known not to hold in every case; the gap is described                                                 |

## Integrity

| Id  | Invariant                                                                                                                      | Enforced by                                                                               | Evidence                                                                                                                                                                                                     | Status   |
| --- | ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| I1  | A recipient MUST NOT report a transfer complete unless every record verified against the accepted contract's labels.           | Receiver rules (`parcel.md`); `libraries/parcel` `openRecord` and label pages             | Parcel tests: any single bit flip, truncation at any byte, data after the last record, reordering and duplication, records spliced from another parcel; e2e byte-identical in every scenario; chaos `replay` | tested   |
| I2  | A wrong link MUST be rejected from the header alone, before any content is processed (key commitment).                         | Header key commitment (`parcel.md`, "Key derivation")                                     | Parcel "the wrong secret, reported from the header alone"; e2e "wrong key: a damaged link fails on the recipient"                                                                                            | tested   |
| I3  | No content MUST flow before the recipient accepted the exact contract digest (names and sizes).                                | ADR 0012; sender waits for `accept` with the digest                                       | e2e "the recipient reviews the contract before any content"; parcel "produces a different contract under a byte-identical header, which a receiver pinning the digest rejects"                               | tested   |
| I4  | A sender whose source file changed MUST stop at the first record that no longer matches its label, never sending a mixed file. | `libraries/parcel` sender rules                                                           | Parcel "stops with source-changed at the first record that no longer matches its label"                                                                                                                      | tested   |
| I5  | Wire input MUST be decoded at the boundary, and anything that does not decode is ignored or refused, never trusted.            | Valibot schemas in `libraries/transport` (ADR 0020); `decodeControlMessage`, `decodeUnit` | `room.test.ts` "nothing before join" (binary frames, other messages and non-messages before `join` are refused); integration checks of malformed rooms and paths                                             | enforced |

## Liveness and recovery

| Id  | Invariant                                                                                                      | Enforced by                                                                  | Evidence                                                                                                                                                 | Status |
| --- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| L1  | A transfer interrupted by a dropped connection MUST resume from what is missing, and end byte-identical.       | Rejoin with backoff (`connection.ts`), `want` ranges (ADR 0013)              | e2e `resume` (clean cuts) and `half-open`; chaos `cut-clean`, `cut-half-open`                                                                            | tested |
| L2  | A socket that goes silent without closing MUST be noticed within 20 seconds and replaced.                      | Liveness pings (`protocol.md`, "Liveness"), `setWebSocketAutoResponse`       | Chaos `blackhole` (seed 2 found the bug); lab "router drops everything for 30 s"; integration "a ping is answered with pong"                             | tested |
| L3  | When the direct path fails or never opens, the transfer MUST continue over the relay.                          | `direct.ts` close handling, recipient re-accepts on `relay` (`recipient.ts`) | Chaos `direct-drop`; lab symmetric NATs, UDP blocked, router moves                                                                                       | tested |
| L4  | A stalled transfer (records missing, none arriving) MUST ask again for what is missing.                        | Recipient stall check every 5 s (`recipient.ts`)                             | Chaos `stall`                                                                                                                                            | tested |
| L5  | A newer join of the same role MUST replace the older one; the replaced socket is told why and stops rejoining. | `room.ts` eviction, close code 4000, client stops on `error`                 | `room.test.ts` "replaces the present sender with a newer sender join, without telling recipients it left"; integration checks of eviction with code 4000 | tested |

## Gaps

| Id  | Gap                                                                                                                                                                                                                                                                                                               | Why it matters                                                                                                                                                                     | Next step                                                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | The room and relay service conformance suites run against the reference layers only; `platforms/cloudflare` implements the room in `room.ts` and `roomObject.ts` and does not run them.                                                                                                                           | The guarantees above for R1 and the room's capacity and admission rules are proven for the model, not for what is deployed. CLAUDE.md requires every platform to pass every suite. | Run the room and relay suites against the platform's adapters (step 2 of the documentation plan).                                                 |
| G2  | The sender's life cycle and the connection are plain code in `apps/web`, not transition tables (the recipient's is a table since spike 0006: `apps/web/src/recipientPhase.ts`). Their states (`waiting-for-recipient`, `transferring`, `reconnecting` and so on) and which events are legal in each are implicit. | Illegal states cannot be listed, so they cannot all be tested. The silent socket (L2) was such a state: joined, but dead.                                                          | Express both as `libraries/machine` tables, generate the spec's diagrams from them, and test every (state, event) pair (step 3).                  |
| G3  | The main app pages carry their CSP as a `<meta>` tag, which cannot set `frame-ancestors`; no header forbids framing them.                                                                                                                                                                                         | Another site can frame the app and trick clicks (clickjacking).                                                                                                                    | Add `frame-ancestors 'none'` as a header for the app's pages, keeping `'self'` for the preview frame (threat T9).                                 |
| G4  | Acceptance is not authenticated: the contract digest is computable from public bytes, so a relay can forge `accept`.                                                                                                                                                                                              | Harmless while acceptance only gates when content flows (`parcel.md`, "Threat model notes").                                                                                       | MUST be MACed under a key derived from the link secret before acceptance authorizes anything.                                                     |
| G5  | Decoders are tested with chosen inputs and property tests, not fuzzed with arbitrary bytes over time.                                                                                                                                                                                                             | Parsers of untrusted input are where memory-safe code still fails (crashes, hangs, the polynomial regex found by CodeQL).                                                          | Fuzz `decodeHeader`, `decodeManifestJson`, `decodeControlMessage` and `decodeUnit` with fast-check's arbitrary bytes, then a long-running fuzzer. |
