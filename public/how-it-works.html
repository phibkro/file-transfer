How it works

You pick files and your browser encrypts them. You share a link. The recipient's browser downloads every piece, checks it, and decrypts it. The server in the middle passes encrypted pieces along and never holds a key.

One transfer

  1. Sealing. Your browser makes a random 32-byte secret, derives keys from it, and encrypts the files and their names into a parcel, a format specified in the open (parcel v1).
  2. The link. The secret goes in the part of the link after #. Browsers never send that part to any server. You share the link however you like: copy it, use your phone's share sheet, or show a QR code.
  3. The room. The server opens a room that admits only a browser that proves it holds the link. It stores a hash of a token derived from the secret, never the secret.
  4. Review. The recipient's browser decrypts the list of files and shows names and sizes. Nothing downloads until the recipient accepts.
  5. Transfer. Encrypted pieces flow through the room. Before any content, the recipient receives a fingerprint of every piece, and checks each piece against it as it arrives. If either side loses its connection, the transfer resumes where it stopped.
  6. Done. Files appear only once every piece has checked out. They stay in your browser until you save them or leave the page.

What the server sees, and what it never sees

Never Sees
What is in your files That a room exists, and when it is used
File names, types, and how many files (beyond a rough bucket) The total size of the encrypted parcel, and how fast it moves
The link's secret, or any key The network addresses of connected browsers, as any server does
Your saved files Counts for the operator: rooms, completed and failed transfers, bytes relayed

For limits, the server keeps a salted hash of a network address for one hour, never the address itself. The full list of what a server keeps is on the privacy page.

Today, and what comes next

  • Direct when possible. When both browsers allow it and the network lets them, encrypted pieces go directly between them (WebRTC). Otherwise, or when a direct connection drops, they go through the server's relay, and the transfer carries on from where it was. Either way they are encrypted end to end. A direct connection shows each side the other's network address; see privacy.
  • No files on servers. A room holds a token hash and a byte count, and is deleted a day after everyone leaves. Encrypted storage for recipients who are offline is a later, opt-in feature.
  • Large files. Transfers of 10 GB have been tested from end to end. Instances with the default settings relay up to 25 GB per transfer.
  • Anyone can run it. The software is free under the AGPL. See run your own.
